# Phase 9 給 Owner 的一頁摘要

狀態：**這只是設計稿，還沒有授權製作或執行。**

日期：2026-08-03

## Threat model（這份設計防什麼）

來源：`05_VERIFIED_LONG_TERM_PLAN.md` §6.16，commit `e34ca1c`。

> 在範圍內（設計必須擋住）：模型過度熱心、誤解授權、自作主張、把顯示當授權、意外重放、崩潰後誤續跑。
>
> 明確不在範圍內：一個刻意規避的對抗性模型。
>
> 已知並接受的殘餘風險（不得再被當成待修缺陷）：模型可經 `wsl.exe -u root` 取得 root；gate 程式碼與 `.venv` 對模型可寫；burn ledger 與 frozen artifact 可被有意刪改；`~/.openclaw/` config 可被有意竄改。

白話說：本設計要防模型太熱心、看錯你的意思、重複做一次，或當機後以為
還能繼續；不保證擋得住一個故意作弊、故意取得最高權限再改程式的模型。
它採用「程序約束＋盡力技術隔離，對非對抗性模型有效」。

## 那天會發生什麼（三句話）

1. 你先看一份「只問問題、不改業務資料」的任務、模擬證據與最後檢查結果。
2. 你本人在場確認後，系統把單次許可先標成已用，再讓 OpenClaw 最多問一次；成功、失敗、逾時都不自動重試。
3. 系統記下結果、確認門已關閉並做一次假的重放測試；真的第二次 OpenClaw 呼叫不會被安排。

## 必要名詞（每個只講一句）

- **OpenClaw**：本系統裡負責做那一次無害查詢的執行者。
- **證據包**：執行前的模擬結果，讓你知道預計做什麼與預期副作用。
- **審批包**：把動作、目標、風險、逾時與停止方法整理成可閱讀的單子。
- **凍結資料**：已算好摘要碼、之後不得悄悄改內容的執行前資料。
- **摘要碼**：像資料指紋；內容改一個字，指紋就會不同。
- **單次密碼（token）**：只綁這張單、這個動作與這次在場時段的臨時密碼。
- **遮罩引用**：用不洩漏密碼的短標記，讓你的文字指令能指向正確那一組密碼。
- **安全通道（OOB）**：不在模型聊天室或模型終端裡輸入、顯示原始密碼的路徑。
- **不同系統身分（不同 uid／使用者）**：用另一個本機帳號操作安全通道，降低不小心互相看到資料的機會。
- **執行閘門（gate）**：全部檢查通過才放行一次，之後回到拒絕狀態的檢查程序。
- **預檢（preflight）**：執行前的總檢查；任何一項缺少、不確定或改變都停止。
- **第二道挑戰**：就在單次密碼作廢前，再出一道新的問題確認你仍本人在場。
- **作廢（burn）**：在呼叫 OpenClaw 前先留下「這組密碼已花掉」的紀錄。
- **稽核鏈（audit chain）**：每筆安全紀錄扣住上一筆，讓意外斷鏈容易被發現。
- **格式規則（schema）**：機器用來拒絕欄位錯誤的規則，本身不是執行許可。
- **復原（rollback）**：出事時怎麼回復；本次查詢不寫業務資料，正常結果為不需復原。

## 本設計直接定案的最小架構

以下是設計結論，不再把每個技術細節都丟給 Owner 選：

| 項目 | 設計定案 | 理由 |
|---|---|---|
| 密碼輸入 | `OOB-C`：Owner 在不同本機使用者擁有的專用終端輸入；不得使用模型所在的同一工作階段或終端 | 新威脅模型接受本機不同身分的盡力隔離；同終端仍可能讓非惡意模型不小心讀到 |
| 安全顯示與摘要核對 | `E-A`：同一專用終端只向 Owner 顯示；完整 packet/action 摘要碼也由該終端獨立顯示 | N=1 最少新設備，同時避開模型聊天室與模型終端 |
| 密碼來源 | `T-B`：另外授權的產生器隨機產生一次，Owner 看見後親自經 `OOB-C` 回送 | 比人腦想密碼更難猜，又比新增專用驗證器簡單 |
| 格式 | `S-A`：新增 Phase 9 專用授權格式，舊 v1 審批包繼續只能是 `null` | 不削弱 Phase 4「舊審批包走不到執行」的保證 |
| 作廢證明 | `B-C`：作廢事件進稽核鏈，且必須先寫成功再呼叫 | 重開程序後仍能拒絕重放；但須另取得 Phase 9 audit 寫入授權 |
| 有效時間 | 產生後最多 10 分鐘，且 Owner 在場時段一結束就提早失效 | 縮短誤用窗口，不讓密碼帶到下一次工作階段 |
| 拒絕上限 | `N=1`：第一次無效、錯誤或不一致就凍結整場 | N=1 演練沒有「多試幾次」的必要，最符合 fail-closed |
| 摘要遮罩 | 每次工作階段的新 HMAC 遮罩標記，不使用公開 token 雜湊 | 避免短密碼被離線猜測；短標記只供人類對照，不當驗證本體 |

若專用不同身分終端無法準備，這份設計不會偷偷改用聊天室或模型終端；應停止
並另提離機裝置方案。不同本機身分只防不小心，不防故意取得 root 或改程式。

## Owner 當天要做什麼

| 動作 | 你要看／說什麼 | 約需時間 |
|---|---|---|
| 1. 看證據 | 核對問題、目標、逾時、預期答案與「不寫業務資料」 | 5–10 分鐘 |
| 2. 看摘要碼 | 在專用終端核對凍結資料的兩個完整摘要碼 | 約 2 分鐘 |
| 3. 保持在場 | 回答第一次確認與作廢前的第二道新挑戰；不對就說「停止」 | 2–5 分鐘 |
| 4. 另給執行指令 | 只有實作和獨立審查都通過後，才用自己的話准許那一發 | 約 1 分鐘 |
| 5. 看結果 | 確認只嘗試一次、沒有自動重試、紀錄可驗、門已關閉 | 5–10 分鐘 |

合計約 15–30 分鐘。你說「停止」、離線、沒回答或表示不確定，都會結束本場。

## 系統會做與不會做的事

系統會：驗證凍結資料；執行兩次在場確認；在呼叫前先作廢單次密碼；最多嘗試
一次無害查詢；把結果分類；關門；用假的執行器證明同一密碼重放會被拒絕。

系統不會：經 worker、queue 或背景排程；寫 Google Sheet 或業務資料；把原始
密碼放進聊天、檔案、參數、紀錄或錯誤訊息；因失敗、逾時或看不懂答案而重試；
把這次成功變成長期許可；在你不在場時繼續。

若出現疑似故意取得 root、改 gate／環境、刪改作廢紀錄或凍結資料、竄改
OpenClaw 設定的跡象，系統要立即停止、保留現有證據並回報你。這些風險是
「已接受但未解決」，不是可以繼續執行的理由。

## 這個選案不代表什麼

**選案 ≠ 實作授權 ≠ 執行授權。**

你在上面接受設計，只代表「可以把這個方案當成下一步規格」。它不准許寫
gate、發真 token、改 schema、增加 Phase 9 audit 寫入，或呼叫 OpenClaw。
之後仍須另有一張精確實作授權；實作完成且獨立審查通過後，執行當天還要你
本人在場，再給只限那一發的精確執行指令。任何一層都不會自動包含下一層。
